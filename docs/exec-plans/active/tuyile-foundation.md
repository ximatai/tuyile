## 2. 交付节奏与通用退出条件

每个阶段作为完整交付完成后统一提交，由主代理亲自实现；随后自查和一次独立 review。发现问题由主代理修复，并由原 reviewer 在 fresh 上下文验证收尾；修复 amend 到该阶段提交，不新增子阶段提交或第二个 reviewer。

阶段内任务用于解释依赖和验收，不代表新的小阶段。不得仅交付骨架、TODO、假结果页面或部分链路就宣称阶段完成。外部授权尚未取得的真实迁移/费用/上线操作明确列为未执行，不混入技术检查通过结论。

所有代码阶段都必须满足：

1. 包管理器、Node 和依赖已固定；迁移、类型检查、构建和测试脚本可复现。
2. 核心规则有单测，涉及数据库锁/事务/约束用真实 PostgreSQL，相关 UI 用浏览器；不能用内存替身证明并发正确性。
3. 测试独立数据库、卷和端口，使用假 Provider 和账号；测试凭据、输出、数据库、日志和机器路径不入库。
4. 失败/空态/冲突/权限不足可理解；现有已交付能力不因后续阶段退化。
5. 新工程与旧工程/原服务的源码运行目录、构建产物、数据库和配置隔离。旧服务只作为行为参考，禁止在其服务 checkout 构建或运行新迁移。
6. 相关文档同步，提交内容无 Key/私人内容/运行产物；主代理自查与独立验证结论可核对。

阶段 1 建立命令：`pnpm typecheck`、`pnpm build`、`pnpm test:unit`、`pnpm test:integration`、`pnpm test:e2e`、`pnpm db:migrate`。这些命令的实际结果记录在阶段 1 验证记录中，不能仅因定义脚本就宣称通过。只重跑受影响检查；文档交付仅做链接、规则和可实现性验证，不跑空构建。

## 3. 阶段 0：架构复核与文档基线

**完整目标：** 将已确认诉求转化为内部一致、可执行、可验收的工程边界。

交付产品基线、架构设计、本计划和文档索引；建立本地 Git 与最小忽略规则，保存设计成果，不创建远程仓库或发布。

验收：

- 会话与任务执行权限分离，普通注销不会取消任务；停用/重置不会被后台执行绕过。
- 单 Worker 领取、幂等、未知结果、额度结算和文件清理有一致的权威来源与失败路径；不引入逐任务租约、接管或可靠事件流。
- 前端轮询已提交状态快照；引用与删除互斥，数据库/文件之间不声称共同事务。API 单独重启不会误伤健康 Worker 的任务。
- 技术建议、已确认业务和未来需批准的外部操作分开；阶段 1—4 可按依赖推进。
- 链接、文档结构、冲突措辞及私密信息检查通过；统一提交后自查和一次独立 review。

**退出条件：** 所有文档审阅问题已处理或明确记录无法绕过的外部决策，文档 Git 工作区干净。阶段 1 代码启动作为后续具体工作，不在本轮暗中开始。

## 4. 阶段 1：可运行工程与账号/工作区基础

**完整目标：** 新工程可独立启动、迁移和测试，管理员能建立指定账号，用户能登录并创建自己的项目，为后续任务执行提供明确边界。

实现范围：

- 建立 Web/API/Worker 独立组合入口和按模块组织的 core/contracts/infrastructure；版本固定、CI 本地同命令。
- 建立显式配置解析、连接池、版本化 SQL 与独立迁移命令；应用启动只校验 schema，不隐式改库。
- 实现账号/会话/激活/重置、personal workspace/成员、项目创建/列表和访问上下文；迁移角色与运行角色分离。
- 只建立本阶段账号/工作区/项目所需 schema 与关键唯一/复合外键约束；任务、额度、资产和 Agent 表随后续实际链路增加，不提前铺设事件或调度平台。
- 实现最小登录/激活/账号管理/项目界面及统一工程蓝基础组件；后台 Worker 可受控启动/关闭，阶段内不调用真实模型。
- 提供隔离 Docker Compose、health/readiness、假测试环境及单测/PG 集成/浏览器测试基础。

验收：管理员初始化无默认密码；账号创建激活、禁用/启用、重置和多设备会话符合基线；匿名 401、角色 403、跨账号/工作区 ID 404；项目和数据库关联不能跨 workspace；运行身份不能执行迁移。Web/API/Worker/PostgreSQL 可独立启动与关闭，fresh 数据库迁移及重复迁移行为可复现。

**退出条件：** 真实 PostgreSQL 和浏览器完成账号→个人项目链路，类型/构建/相关测试及独立 review 通过；没有以 TODO 挡住下一阶段必需的授权/数据接口。

## 5. 阶段 2：单 Worker 后台创作与额度闭环

**完整目标：** 登录→新项目→提交一次假服务生图→关页/普通注销→Worker 完成→重新登录查看图片、进度与额度，全流程不依赖浏览器执行。

实现范围：

- 实现直接生图/参考图任务准入、允许模型/规格校验、整单预留、共享限额、有界队列及稳定幂等身份。
- 单 Worker 启动互斥、条件领取、进程内并发控制、短事务 dispatch、配置/密钥版本、安全重试和取消/撤销；中断后标失败/部分完成，unknown 保留待核验，不自动续跑或刷新预算。
- 实现私有原图/预览、受限上传解码、staging/安全发布/数据库提交、存储预留和物理回收计量；文件核验与清理不恢复模型执行。
- HTTP 命令、任务详情与列表；前端轮询完整状态快照、重新打开页面查询已保存结果，不建立持久化事件流、游标或 SSE。
- 实现最小创作/任务/图片结果和个人额度页面、基本管理对账入口；不以静态模拟任务替代 Worker 实际执行。
- Server 和 Worker 共同使用相同用例/事务边界，任务输入和引用不随会话记录清理消失。

验收必须包含：

- 第二 Worker 被启动互斥拒绝；唯一 Worker 的轮询不重叠领取，执行槽满仍可排队、队列满才拒绝；用户/全局执行并发均受限。
- dispatch 前/后、文件同步/发布/DB 提交前后终止 Worker；原 running 失败或部分完成，已 ready 结果保留，未知不重发。原 queued 只经正常授权/预算/过期检查启动，不续跑旧运行步骤。
- Worker/数据库正常时，关页、刷新、断网、普通注销与会话清理后后台继续；API 单独重启也不取消任务。停用/重置与 dispatch 竞争遵守在途分界。
- 并发准入、幂等同键冲突、部分成功、跨日图片预留、当日尝试预算、降额、未知保留和幂等人工处置。
- 轮询只读，重复查询不重新执行；提交响应丢失使用原幂等键找回任务，查询失败不触发取消或新提交。
- 原件/预览/下载/引用与错误详情双向隔离，管理查询不暴露正文或 Key。

**退出条件：** 独立浏览器关闭/重新登录验证后台结果，真实 PG 并发与故障注入通过，Docker 全链路及独立 review 通过。未完成 Agent 全套和画布功能时明确属于后续阶段，不能宣称整个产品已完成。

## 6. 阶段 3：完整创作工作台与管理能力

**完整目标：** 达到已确认首版创作范围，保持单 Worker 后台链路和数据隔离。

**治理前置与集成要求：** 按 [架构专项治理](../../architecture-governance.md) 的 G1—G6 实施用例/事务边界、任务/输出/资产与额度模型、查询与锁范围、前端状态管理、独立规划/图片配置及能力、技能/可信工具注册。先落实依赖边界再接入对应功能，均纳入本阶段完整提交，不拆小阶段。图片核验改为本地成功输出才计次；专项验收与原有 M3 验收共同构成退出条件。当前仅形成治理文档，代码治理未开始。

实现范围：

- React Flow 自有文档、图片/任务/分组、来源关系、选参考/继续改图、复制/移除/撤销重做/对齐/视图保存。
- 明确项目级 editor store、revision 保存队列/冲突保留、延迟响应 scope/epoch、输出 placement receipts，不全局拦截 fetch。
- Agent 规划、澄清、一次有界格式修复、不可变确认版本、整计划预留与依赖调度；Worker 持有执行，浏览器只确认/查询；首版按依赖顺序执行，不建设通用 DAG 调度器。
- Gallery 跨项目复用、下载/导出/引用保护，提示池白名单、个人收藏/分组；项目删除保留图库原件并与任务准入互斥。
- 完整账号启停/重置、额度/允许模型、Provider/全局技能管理、脱敏统计/错误/审计/对账。
- A 效果图布局/B 折叠窄轨、中大型桌面视口；其余页面遵循逐页沟通的方式校准，不从概念图推导新功能。

验收：完整创作主流程；计划超额整单拒绝、不降质；内部重试/修复不重扣规划次数；未确认草案不执行；刷新读取当前状态不发起新调用；Worker 重启不续跑原 running 计划，已保存结果可查，未知步骤保留待核验；重复轮询不重复落图，移除节点不复活；画布编辑不产生模型调用；删除/引用竞争和取消中保护；中大型桌面无关键遮挡、焦点及操作反馈正常。前两阶段的权限、后台与额度回归仍通过。

**退出条件：** 完整首版工作台端到端、中大型桌面视觉核对、类型/构建/单元/PG 集成/浏览器/Docker 和一次独立 review 通过，无占位功能或未声明的行为缺口。

## 7. 阶段 4：迁移工具与发布验收

**完整目标：** 可审阅、可演练、可恢复地从旧格式导入新工程，产出正式部署所需的操作与验证材料。

实现范围：

- 受控离线 SQLite 只读导入、ID/归属映射、完整性报告、分批检查点/幂等重放，覆盖旧单用户及已有 workspace 两种来源。
- 旧原图、生成记录、对话、收藏和画布转换；保留原始快照，报告未知图形/裁剪/未恢复对象，不静默猜 owner 或补成功状态。
- 迁移/原件核验只在目标副本写入；符号链接和不自包含备份明确拒绝或按已验证规则处理，不访问任意外部目标。
- 镜像、独立 Compose、HTTPS/轮询代理模板、schema 兼容检查、停写迁移和切换/回退手册、密钥与备份恢复说明。
- 合成 fixture 导入→启动→双账号访问→后台生成→停写完整备份→新库/新卷恢复，核对原图哈希/关系、任务与额度。
- 核对保留许可证和第三方素材来源；公共提示池不宣称商业授权素材包，禁止恢复公开云回退/OAuth。

验收：缺图/损坏/越权映射/中断导入/重复导入均有正确结果；真实 PG 和文件卷一起恢复，旧备份与原服务未覆盖；HTTPS/轮询及资产隔离通过；备份恢复只核对已保存内容与结算，不承诺恢复执行。操作手册能区分“技术演练通过”与“真实迁移已完成”。

**退出条件：** 工具、合成迁移与备份恢复、部署材料和一次独立 review 通过；列明真实数据、真实模型、域名/主机等尚未执行事项。真实迁移与上线是下一项需单独授权的操作，不以缺少这些授权为由伪称已经验证真实数据。

## 8. 正式迁移与上线操作（独立授权）

在技术交付完成后，确认目标主机、域名/证书、资源/数据库和备份位置、主密钥保管、维护窗口及恢复目标。随后经授权执行私有来源盘点、完整备份、真实副本演练与报告审阅；只有明确接受报告和待处理项后才安排正式切换。

真实模型兼容烟测须明确 Provider/模型、次数及费用范围。历史公开对象访问撤销单独决定，不自动改桶权限或删除对象。切换后的新内容在回退前先导出核对，禁止直接恢复旧库把新作品覆盖掉。
