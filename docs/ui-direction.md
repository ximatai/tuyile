# 已确认的 UI 方向

以用户认可的 A（project sidebar）效果图为主，收起导航借鉴 B（canvas first）的窄轨。工程蓝继续沿用。用户最新确认：优先中大型屏幕，不再投入小屏幕专用适配。

## 桌面工作台

- 单一紧凑顶栏：品牌、当前项目、保存状态、额度和账户入口，避免重复标题挤占创作区域。
- 左侧固定导航和项目列表，当前项目明确高亮；折叠为 B 的图标窄轨，中央区域随之扩展。
- 中央占据主要空间，图片是视觉主体；完整工作台使用浅色点阵画布、清楚的选中边框和就近的图片操作，避免把整个创作区做成管理表单。
- 右侧白色创作面板，提示词和参考图优先；模型、尺寸、质量和张数紧凑排列，次要设置折叠。提交主操作固定可见，参数区可滚动；额度反馈与按钮不重叠。
- 不把效果图中的占位文字、示例图片、未确认的工具按钮当成新增业务要求；实际能力按产品基线和阶段计划交付。

## 实现与核对

### Agent 交互：方案一（2026-10-29 已确认）

- 保留 A 布局及 B 折叠窄轨；右侧采用“直接创作 / Agent”页签。
- Agent 在对话中展示计划卡，包含步骤、参考图和图片预留摘要，提供修改计划入口及继续描述需求的输入区；不采用方案二的独立“当前计划”分区。
- 确认操作及额度预留摘要固定可见，对话和计划内容可滚动，不遮挡输入或主操作。用户确认前不启动计划生图，修改后确认对应的新计划版本。
- Skill 是可复用的创作方法；计划是根据本次需求、参考图与技能生成的具体执行方案。计划卡用于审阅本次执行内容，不作为技能编辑入口。
- 图中示例图片不代表未确认计划已执行。“生成后会通知你”及未经验证的耗时文案不纳入实现，继续采用已确认的 HTTP 轮询规则。
- 选定效果图保存在忽略目录 `.codex-temp/design-reference/agent-inline-plan-approved.png`，仅供视觉对照，不进入应用素材或 Git。

### 验证要求

标准控件使用 Ant Design；共享组件只负责工程蓝主题、布局和业务组合。画布使用 React Flow，不重新实现通用控件或图形引擎。

### 信息与交互校准（2026-10-30）

- 用页面分区、控件名称和状态解释操作，删除重复副标题与流程段落。字段仍保留可访问名称；布局已说明含义时可隐藏重复的视觉标签。
- 风险、失败原因、额度预留与确认操作就近可见。补充规则放入可点击、可用键盘关闭的 Ant Design Popover；图标操作和收起的导航使用 Tooltip，次要动作使用 Dropdown。
- 长提示词使用可展开的 Typography 段落；任务明细使用 Collapse；模型目录使用 Table 的有界滚动。保持原生滚动条与稳定滚动槽，避免整个页面与局部区域争抢滚动。
- 长表单使用 Drawer 的固定 footer，不手写浮动保存按钮；跨模型池修改使用 Affix，只有待发布时显示。验证 1440/1920 桌面、弹层边界、Esc、焦点返回和关闭动画后的下一步操作。

### 统一密度（2026-10-30）

采用 Ant Design tokens 统一常规控件32px、辅助按钮28px、正文13px、辅助12px，页面标题22px、区域标题16px、卡片/浮层标题14px；统计数字22px。保留品牌层级，小字不低于12px，不使用整体缩放。自定义页面同步采用16px卡片内边距、10–12px表单间距和更紧凑的导航行距，右侧创作面板收敛至360–440px，画布和图片保留主体空间。核对登录、账号、所有内容页面、管理页签、抽屉与浮层，确保字号协调、操作可达和滚动正常。

生成反馈持续显示在主按钮旁及画布可视区：提交时立即loading，接受后区分排队和生成，显示实际已保存张数，完成/部分完成/失败/取消/待核验分开表达。读状态失败不冒充实时生成，提交结果未知不提示成功，不自动新建任务。状态提示不依赖展开历史、画布世界坐标或页面保持打开，不虚构百分比与预计时间。

主要核对 1440×900、1920×1080，并检查更宽桌面上的空间利用。核对展开/折叠、项目切换、参数滚动、主按钮可见、图片预览和焦点操作。现有基础响应式可以保留，手机专用抽屉和切换不再作为后续验收要求。

阶段 2 交付后台创作的最小结果界面，不把它当作完整画布的最终视觉稿；阶段 3 按 A 的整体构图整合完整工作台，不重新另起视觉方案。
