# 图片创作能力升级专项治理方案

制定日期：2026-11-05。状态：第一阶段已实现并完成审查；第二至第五阶段尚未开始。当前实际能力见路线图，阶段范围保留作为验收依据。

本文是当前活跃工程计划，记录已确认的产品方向、实施范围和验收门槛。它不表示相关能力已经实现，不授权真实付费调用、公开部署或私人数据迁移。当前已实现行为仍以[产品基线](product-baseline.md)、[架构设计](architecture.md)和[当前能力](delivery-roadmap.md)为准；阶段交付时同步更新这些说明及[界面规范](ui-direction.md)。

## 1. 目标与产品定位

图一乐定位为以项目画布为中心的 AI 视觉创作工作台，帮助用户逐步做出可用作品，并围绕项目持续创作。服务个人及小团队成员的使用场景；本轮仍采用独立个人工作区，不引入团队共享。

目标优先级依次为：做出可用作品、围绕项目持续创作、探索灵感。主要创作链路为：

> 表达需求 → 探索方向 → 选定作品 → 局部修改 → 衍生素材 → 导出使用。

近期主要服务海报配图、商品展示图、社交内容、插画和简单图标。准确的专业文字排版、印刷交付、复杂矢量编辑不作为本轮承诺。画布组织方向、参考、作品及来源关系；Agent 将需求转为可审阅方案；编辑弹窗承担局部标注与结果比较。

## 2. 已确认的设计原则

### 2.1 主动推荐、明确控制、按场景展开

- 模型、尺寸、画质、张数等常用选择直接可见，模型展示明确版本，实际调用身份不因简称改变。
- 复杂度等进阶能力按需展开；圈选工具从图片修改入口进入；SVG 专属选项仅在矢量创作场景出现。
- 系统提供合理初值与推荐，用户明确设置后保留选择。模型能力、管理员开放范围与个人策略仍共同约束有效值。
- 换模型、降规格、追加生成及扩大任务范围由用户明确选择。历史参数失效时提示处理，不静默改成另一套配置。
- 保持工程蓝、A 三栏工作台与 B 折叠窄轨，面向中大型桌面。标准控件与弹层使用 Ant Design，自定义组件限于领域行为和画布。

### 2.2 Agent 主动规划，确认后执行

- 信息足够时主动提出方向、素材组合、模型、规格与步骤，并说明重要假设。只有缺少会明显改变方向的信息时才追问。
- 规划允许推荐先出一张主视觉，用户选定方向后再衍生配套素材；支持审阅、修改及选择部分步骤。
- 图片执行始终需要明确确认，展示产物、参考素材与预计图片预留。规划本身沿用现有规划计次规则，不属于免费生成。
- 确认后只完成约定范围。新增调用、换模型或增加交付内容需用户选择；结果后的建议不会自行触发模型调用。
- 选择部分步骤时必须满足依赖闭包并重新计算整单预留，不允许执行缺少输入的下游步骤。详细交互与事务设计在第二阶段完成。
- 依赖闭包中的输入可以是本次明确执行的前置步骤，也可以是用户选定、经授权校验的既有成功资产；不能因继续创作隐式重新生成已完成的祖先步骤。

### 2.3 修改成为核心流程

- 从画布图片进入独立编辑弹窗，明确原图、标注和修改需求。
- 每次修改形成独立结果，原图继续保留；画布记录作品来源，比较入口便于判断目标变化及其他区域变化。
- 第一版提供圈选、画笔、撤销、清除、生成和并排比较。复杂选区、图层、路径及像素编辑不进入本轮。
- 标注用于引导模型，不保证圈外像素完全不变，也不保证文字逐字准确。

### 2.4 逐步投入，诚实反馈

- 提供“快速探索”和“精细创作”推荐配置，默认首次一张；允许用户直接选择高质量或批量生成。
- 推荐配置展示实际模型与参数，不自动更改已有个人策略、配额或历史草稿。具体初值经能力校准和后续实测确定。
- 提交前显示预计占用的生成额度；费用有可靠依据才估算，缺失不当作零，也不将估算作为账单上限。
- 等待显示排队、执行及已保存结果，不编造进度和剩余时间；离开页面不影响已接受任务。
- 失败保留输入、标注和成功结果。未知结果先核验，不自动重发；明确失败后的用户重试仍为新准入与新预留。

### 2.5 新产物的优先级

SVG 纳入本轮，先完成生成、预览、保存和导出。矢量路径编辑交由后续工具；用作参考编辑时明确使用栅格副本并保留原件。GIF 保留为后续方向，本轮不增加动画任务、播放器、帧参数或多帧资产支持。

## 3. 官方依据与当前差距

核对日期：2026-11-05。官方更新日志记载 2026-11-04 发布 `gpt-image-2.6-sunburst`、`gpt-image-2.6-flare`，新增复杂度控制、SVG、GIF，并为支持的 2.5/2.6 模型增加标注引导编辑。能力来源为官方文档核对，尚未在本专项中进行真实付费验证。

| 依据 | 对本专项的约束 |
| --- | --- |
| [官方更新日志](https://developers.openai.com/api/docs/changelog) | 精确记录模型身份和发布日期，不将其描述成所有旧模型统一升级 |
| [图片生成指南](https://developers.openai.com/api/docs/guides/image-generation) | complexity 与 quality 分开；标注、栅格及矢量按对应端点能力接入 |
| [生成接口](https://developers.openai.com/api/reference/resources/images/methods/generate) | SVG 要求 n=1、不支持编辑输出；svg_usage 独立于图像渲染用量 |
| [编辑接口](https://developers.openai.com/api/reference/resources/images/methods/edit) | 核对 markup 的传输、输入组合及限制，不将其等同于现有参考图 |
| [官方价格](https://developers.openai.com/api/docs/pricing) | 价格快照按模型与调用路径核对，不能由相同费率推断单张成本相同 |

实施前重新核对对应接口的限制、用量结构与服务可用性；`/models` 只证明标识可发现，不证明参数兼容。第三方兼容服务不得仅按模型名称继承全部官方能力。

当前代码差距：

- `packages/contracts/src/image-model-knowledge.ts` 仅校准 2.5 及已知快照，新 2.6 会落入未校准模型处理。
- `apps/web/src/model-presentation.ts` 尚无 2.6 版本展示；推荐能力需同步更新。
- `packages/infrastructure/src/image-provider.ts` 尚未贯通 complexity、markup 或 SVG 请求与响应处理。
- `packages/core/src/model-usage.ts` 未包含 2.6 参考价格映射，也未表达 SVG 编写模型独立用量。
- 创作、草稿及 Agent 等契约目前采用三档画质和 PNG/JPEG/WebP；`image-files.ts` 明确拒绝其他格式及多帧输入。

`xhigh/max` 的开放不作为本轮默认要求。若拟开放，须同时设计个人策略、预算、历史兼容和执行校验；不能仅扩展前端枚举。

## 4. 五阶段实施与验收

五个阶段按顺序推进。每阶段交付完整可使用链路，并在该阶段完成专项验证；第五阶段承担累计集成验收，不能替代前四阶段的正确性验证。

### 第一阶段：Image 2.6 静态图片完整适配

**目标：** 用户可以明确选择 2.6 完成直接创作、参考编辑与 Agent 图片执行，参数保存和结果追溯完整。

**范围：**

- 为两个精确模型标识建立有日期、来源的能力记录，核对尺寸、格式、质量及编辑边界，更新推荐配置和版本展示。
- 接入复杂度声明及用户选择，贯通直接创作、Agent 执行配置、服务端校验、JSON/multipart 请求、草稿、任务快照和历史复用。
- 复杂度与画质独立；对旧任务、旧草稿和不支持参数的服务保留原请求语义，不强行注入新值。
- 补齐 2.6 用量与版本化参考价格映射，单独核对当前 Images 调用路径的计价规则，未知字段继续显示缺失。
- 管理员显式发布新模型；不自动替换默认模型、开放权限或撤销旧版本。

**验收门槛：** 合法配置可完成合成生成、参考编辑与 Agent 确认执行；非法组合在预留前拒绝，执行前仍校验；参数刷新可恢复、历史可复用，同键重试维持原快照；旧任务读取和未校准服务行为兼容。

**验证：** typecheck、受影响能力/协议/费用单元测试、相关真实 PG 配置和任务集成测试、模型选择与草稿复用专项浏览器检查。能力记录标明文档验证与真实验证的差别。

### 第二阶段：探索、精修与 Agent 规划体验

**目标：** 用户能以较小首次投入确认方向，再主动决定精修或衍生，Agent 提供可理解、可调整的方案。

**范围：**

- “快速探索／精细创作”作为可检查的推荐配置，明确应用后的模型、画质、复杂度和张数；不以推荐标签替代真实参数。
- 首次默认一张，批量与高质量可主动选择；已有草稿不被默认配置覆盖，替换用户设置经过明确操作。
- 调整规划指引与计划呈现：说明假设、产物及依赖，只在关键缺口追问，支持先探索后扩展。
- 支持选择部分计划执行，服务端构造不可变的有效执行版本，验证依赖、输入和整单额度；已确认计划不原地改写。
- 步骤采用稳定身份，筛选或重排后仍指向原有依赖，不以展示位置或“上一步”推断输入。首次确认绑定执行版本与操作幂等键，同键同输入返回原执行，同键不同输入拒绝；选择其他步骤形成新的待确认执行版本。
- 用户从成功结果继续时，明确选择使用哪份输出，将其固定为后续执行的资产输入并保留来源；新执行只为新增操作预留和结算，不重复生成或扣除已有资产的生成次数。原执行不自动续跑，失败或未知结果不能冒充可复用成功资产。
- 选定方向后，后续规划显式携带用户选择的作品、需保留的元素、风格与文案，确认时可检查。沿用现有参考图、风格、文案和计划快照，不从历史对话猜测当前方向，不新增品牌管理系统或隐式项目全局状态。
- 后续建议、方案编辑和推荐配置本身不产生额外图片调用；保留规划计次及用户确认边界。

**验收门槛：** 用户看得见实际参数；推荐不越过当前权限与策略；未确认不生成图片；部分执行不遗漏依赖、不重复预留。覆盖先执行 A、选定 A 的一个成功输出后再执行 B/C：不重跑 A，B/C 绑定所选资产，步骤筛选/重排不改变依赖，同键重试不新建执行；所选资产失效时阻止新提交。确认可检查承接作品及保留约束；方案与选择刷新后的恢复行为明确，已有计划仍能读取。

**验证：** 规划/依赖/预算单元测试，计划版本、幂等确认及预留的真实 PG 集成测试，推荐应用、手动调整、部分执行和确认的专项浏览器检查及 typecheck。

### 第三阶段：圈选修改与结果比较

**目标：** 用户可以从已有作品提出局部修改，保留原件、标注和结果关系，并方便比较。

**范围：**

- 画布图片操作进入 Ant 弹窗，自动绑定原图，提供圈选、画笔、撤销、清除和修改需求。
- 标注按原图坐标转换为受限透明图层，明确缩放映射、尺寸和引用数量约束，按支持情况传入 markup。
- 原图、标注和需求形成服务端固定快照，纳入工作区鉴权、存储计量、任务引用保护及删除互斥。
- 从选定方向进入修改时承接用户明确选择的原图、风格、文案及保留要求，并允许检查和调整；更换原图或方向不隐式沿用不再适用的标注，也不丢失其他已编辑输入。
- 修改会话按项目保存到服务端，支持关闭后继续；多标签冲突保留本地修改，明确替换原图时如何处理标注。私人内容不写浏览器持久存储。
- 修改结果经现有文件验证和额度结算形成独立资产，在原图附近避让放置，保留来源；提供并排比较。
- 失败保留输入，部分成功保留输出，取消及未知结果沿用现有规则。服务不支持时说明限制，不静默退化为其他请求。

**验收门槛：** 缩放后的标注位置正确；跨用户原图或标注不可引用；删除、取消和晚到结果不破坏引用及结算；重试不丢快照；弹窗关闭、刷新、项目切换及冲突都有明确保存行为；比较使用明确资产身份，不随列表更新错配。

**验证：** 坐标/标注预算/协议单元测试，原图与标注引用、删除竞争、快照和结算的真实 PG 集成测试，真实弹窗标注、保存恢复、并排比较和键盘焦点的专项浏览器检查及 typecheck。验证构建版弹窗与 CSP。

### 第四阶段：SVG 创作、预览与导出

**目标：** 用户能生成、管理并下载可继续加工的矢量素材，费用与图片额度口径明确。

**范围：**

- 明确矢量创作入口，按服务支持展示模型和参数。只支持文档规定的生成组合，不将 SVG 直接送入图片编辑接口。
- SVG 作者配置由管理员在服务能力中声明：明确服务是否支持作者选择、允许的作者模型及 reasoning 设置；不将普通对话模型池直接视为合法作者目录。普通用户只面对必要的创作选择，无需管理另一套模型参数。
- 支持作者选择时，准入校验并绑定不可变配置中的作者模型与 reasoning；不支持选择时省略相关字段，明确采用服务默认作者，不能承诺预先固定其身份。未获授权或组合无效时在派发前拒绝，不盲传作者字段或静默换作者。
- 请求的作者选择模式、显式配置及响应返回的实际作者分别记录；服务默认模式下真实作者可能变化，重试和费用解释不能假定始终相同。缺失的实际身份或价格记未知，不能以请求模型推算另一作者的费用。
- 建立 SVG 原件校验及受限渲染，限制文档字节、结构复杂度和渲染资源；拒绝脚本、外部资源及不允许的内容，不以内联未验证 XML 展示原件。
- 采用成熟渲染器及受限进程等可隔离执行方式：并发有界，CPU/内存与执行时间受限，超时可强制终止，禁止网络及任意文件读取；异常 SVG 不得拖垮 API 或主 Worker。具体选型须证明资源限制实际生效，不以单个异步超时包装代替执行终止，不建设通用沙箱平台。
- 区分上游结果未知与本地 SVG 校验/预览失败。已收到的原件按明确生命周期保留或清理，无法确认安全的内容不作为可访问作品；本地失败仅对已收到内容进行受限处理重试，不因此重新调用付费生成。预览失败不伪造成功输出或直接消费生成额度，相关存储预留和任务结算须有明确终态。
- 保存矢量原件及栅格预览，贯通画布、图库、收藏、来源、授权下载和现有导出边界；其他仍不能支持的操作明确说明。
- 用作图片参考时显式创建受控栅格副本并记录来源，不覆盖 SVG 原件，不因转换增加生图计次；副本占用存储并纳入引用保护。
- 图像渲染和 SVG 编写模型分别记录用量与价格快照；缺失部分明确标记，不以现有单模型费用记录冒充完整费用。
- 一份成功持久化且通过校验的 SVG 作品计一次生成。服务内部生成、未作为本地成功图片输出持久化的参考图不额外计次；本地成功持久化的中间基准图仍按现有规则计次。SVG 栅格预览及转换副本不计生成次数，但计入存储，不能以是否单独交付改变计次口径。
- 生成接口 n=1 与产品张数分开：如支持批量，每件分别调用并按整单原子预留，不用请求限制隐式拆单；首版产品入口限定单件。

**验收门槛：** 原件、预览及下载均按工作区授权；不支持的编辑及作者配置在付费调用前拒绝；覆盖显式作者选择和服务默认两种模式，实际作者与缺失费用如实记录；用量多组件不丢失、不重复累计。恶意或超限 SVG 的渲染可终止，不访问网络或任意文件，不影响后续正常任务；本地预览失败的重试不新增模型调用、不重复计费或结算。原件校验或预览失败不能伪造作品成功；重试、删除、引用和存储释放符合现有一致性要求。历史栅格资产不受新格式影响。

**验证：** SVG 校验/资源限制、协议和费用单元测试，真实 PG 资产生命周期、权限、存储及结算集成测试，生成至预览/下载/参考副本的专项浏览器检查；运行 typecheck、完整构建及相关构建版 CSP/私有文件检查。

### 第五阶段：完整创作链路与交付验证

**目标：** 探索、选择、修改、衍生和导出形成连续体验，验证累计变更的兼容性与异常边界。

**范围：**

- 用合成项目贯通直接创作与 Agent 两条入口，覆盖探索、精修、标注修改、来源关系、SVG 导出和跨项目复用。
- 安排人工任务验收：从探索结果进入修改无需重复搭建已有输入；修改后能辨认原图与新版本并进行比较；选定作品及保留约束可明确传递到后续衍生；SVG 下载到外部工具后，主要结构、颜色及可编辑性符合该素材用途。用合成素材可验证操作与文件互通，不能据此声称真实生成质量达标。
- 统一排队、等待、完成、部分成功、明确失败和待核验反馈；失败后保留工作，不出现重复生成、重复落图或重复计次。
- 覆盖关闭与重新打开、普通退出后后台执行、会话撤销、Worker 中断、版本冲突、失效模型和跨用户访问。
- 校验历史任务、计划、草稿及资产的读取兼容；如有迁移，验证显式升级与旧数据保留。无相关恢复改动时不额外安排恢复演练。
- 同步产品、架构、界面、模型能力及操作文档，明确实际能力和仍未实测的模型组合。

**验收门槛：** 关键链路、异常检查及人工任务验收通过，记录实际完成的场景和可观察结果；已知缺陷、未完成和环境阻塞如实记录。无真实模型验收时只能说明合成链路与文档适配通过，不能宣称画质、速度或所有兼容服务已验证。

**验证：** 按累计跨层改动运行 typecheck、完整构建、完整单元/真实 PG 集成及关键端到端回归，在候选构建或容器完成受影响冒烟。新增依赖或涉及安全与打包的变化补充相应发布检查；远程 CI 状态以真实记录为准。

## 5. 跨阶段工程约束

- 主代理亲自实现完整阶段，不拆分或委派实现。每阶段一个提交，提交后自审及一名独立审查者复核；修复 amend 该阶段提交。
- 每阶段开始前确定请求/响应、能力声明、持久化版本、授权、幂等、引用、计量和失败语义。依赖或迁移只按实际业务引入，不预建通用媒体平台。
- 画布文档、创作草稿、服务配置及已确认任务各自保留显式版本；新字段缺省兼容旧内容，未知版本拒绝静默覆盖。不能改写已应用迁移。
- 已接受任务绑定配置与输入快照。服务变更、草稿修改或源图变化不改变旧任务；紧急撤销及执行前校验继续生效。
- 单 Worker、有界队列、HTTP 轮询和私有文件卷保持现有架构。未知结果不自动重发，不引入故障切换、重启续跑或高可用承诺。
- 保留工作区隔离、服务端密钥保护与专用管理员作品访问边界；新标注、SVG 原件及衍生副本均不得通过公共静态目录暴露。
- 验证按[开发说明](development.md#验证选择)执行。数据库测试串行，仅允许 loopback55440 的 tuyile_test；不得操作旧工程、LaunchAgent 或复制其凭据、数据及构建产物。

## 6. 真实模型验收与变更治理

真实验收先明确服务、精确模型、参数、样本、调用次数、预算上限和停止条件，取得相应付费授权后执行。建议覆盖商品图、海报配图、简单局部改色、多参考合成和 SVG 图标，比较结果可用性、非目标变化、耗时及可得用量；一次成功仅证明该组合，不作为普遍质量承诺。

作品可用性按具体任务判断：主体与必需元素是否保留、局部修改是否达成且非目标变化可接受、系列衍生是否延续所选方向、SVG 是否能够在外部工具继续加工。将模型效果问题与产品操作阻碍分别记录；不预设未经实测的画质分数、成功率或速度承诺。

原始响应、凭据、真实图片、截图和日志留在忽略目录或运行卷。公共说明仅保留脱敏结论与对应提交；不将实施日志作为公共指南持续累积。公开发布仍需单独授权及发布检查。

阶段顺序、产品范围、计次口径或自动执行边界需要调整时，先明确变化与影响，取得产品方向确认后修订本文。普通实现细节由主代理在已确认范围内决定，无需重复确认。阶段完成时更新实际能力和验证结论；全部完成后从路线图移除活跃计划入口，历史方案与验收依据通过 Git 追溯。

## 7. 明确不纳入本轮

GIF 和其他动画/视频生成、专业矢量路径或像素编辑、团队共享和实时协作、公开作品链接、用户自带 Key、多 Worker 接管、未知结果自动重发、自动故障切换及新增故障恢复机制。保留现行最多一次明确安全的自动网络重试规则，不扩大重试范围或预算。不为未来格式提前建设通用插件、工作流或媒体执行平台。
